# Database

Learnova runs on Supabase (Postgres, Auth, Row-Level Security). `migrations/` holds
every schema change in the order it was applied to the live project, exported
from `supabase_migrations.schema_migrations`.

## Layout

| Migration | What it adds |
|---|---|
| `learnova_foundation_schema` | `profiles`, `curricula`, `subjects`, signup trigger, own-profile RLS |
| `lock_profile_role_from_self_update` | trigger so users cannot promote their own role |
| `learnova_student_core_loop` | conversations, messages, quizzes, questions, attempts |
| `learnova_planner_gamification` | study plan, goals, append-only XP ledger |
| `learnova_parent_teacher_dashboards` | parent-child links, classes, assignments, invite-code RPCs, parent/teacher read policies |
| `fix_ambiguous_column_refs_in_link_functions_v2` | renames RPC output columns that collided with real columns |
| `add_parent_profile_fields` | parent profession / relationship / contact preference |
| `add_written_quiz_support` | `quiz_type` and `model_answer` for written-answer quizzes |
| `expand_curriculum_specific_subjects` | per-board, per-grade subject catalogue |
| `add_admin_flag_and_feedback` | `is_admin` flag and the `feedback` table |
| `admins_can_view_all_profiles` then `fix_admin_policy_recursion` | the first version recursed; the fix uses a `SECURITY DEFINER` helper |

## Access model

- Every table has RLS enabled.
- Cross-user reads (parent to child, teacher to class students) are explicit
  `select` policies. Writes across users never happen.
- Linking by invite or class code goes through `SECURITY DEFINER` functions so
  no table needs broad read access to find a code match.

## Notes

- These files were exported from the live database, not generated by the
  Supabase CLI, and have not been replayed against a fresh project.
- `expand_curriculum_specific_subjects` was rewritten to match rows by name
  instead of the original generated ids so it is reproducible.
